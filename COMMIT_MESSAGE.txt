feat: implement complete database synchronization system for GetSavDown

## Summary

Implemented comprehensive database synchronization solution to maintain identical
configuration data between development and production environments. All 59 tools
are now synchronized between TypeScript definitions and database ToolConfig table.

## Problem Solved

User deploys using dev-first workflow, requiring configuration data (tool settings,
admin flags) to stay synchronized across environments while keeping operational
data (users, payments, downloads) separate per environment.

## Solution Components

### Seed Scripts (2 scripts)
- scripts/seed-tools.ts: Initialize ToolConfig from TypeScript tool definitions
- scripts/seed-admin-settings.ts: Initialize AdminSetting with default values
- Both scripts are idempotent (safe to run multiple times)
- Both scripts preserve existing admin customizations

### Configuration Export/Import (2 scripts)
- scripts/export-config.ts: Export ToolConfig + AdminSetting to JSON
- scripts/import-config.ts: Import configuration from JSON file
- Supports dry-run mode for safe testing (--dry-run flag)
- Protects environment-specific settings from being overwritten
- Does NOT export operational data (users, payments, etc.)

### Verification Tools (3 scripts)
- scripts/check-tool-sync.ts: Verify code/database tool synchronization
- scripts/backup-db.ts: Create configuration backups before changes
- scripts/test-sync-workflow.ts: Automated testing of entire sync workflow

### CI/CD Integration
- .github/workflows/check-tool-sync.yml: Automated sync verification on PRs
- Fails PR if code and database are out of sync
- Posts fix instructions in PR comments

### Documentation (4 comprehensive guides)
- docs/ENVIRONMENT_SETUP.md: Environment setup and sync workflows
- docs/DB_SYNC_IMPLEMENTATION.md: Implementation summary
- docs/TESTING_DB_SYNC.md: Testing procedures and verification
- SYNC_VERIFICATION_COMPLETE.md: Final verification report

### Quick Reference Materials
- .agents/tasks/db-sync-quick-reference.md: One-page command reference
- COMMIT_MESSAGE.txt: This file (commit message template)

## Usage Examples

### First-Time Environment Setup
```bash
npm install
npm run db:deploy
npm run db:seed:config
npm run check:tool-sync
```

### Configuration Sync (Dev → Production)
```bash
# In development
npm run db:export:config
git add config-export-*.json
git commit -m "chore: export config for prod sync"
git push

# In production (after deploy)
npm run db:import:config config-export-2025-01-15.json
npm run check:tool-sync
```

### Safe Import with Dry Run
```bash
npm run db:import:config config-export-2025-01-15.json --dry-run  # Test
npm run db:import:config config-export-2025-01-15.json             # Apply
```

### Backup Before Changes
```bash
npm run db:backup
# Creates: backups/backup-YYYY-MM-DDTHH-MM-SS.json
```
